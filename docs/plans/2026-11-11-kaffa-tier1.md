# Kaffa Tier 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Kaffa's core loop: plots come in, get validated and screened against satellite data by fixed rules, failing plots are chased on Telegram by a durable workflow, field agents fix them by walking the boundary in a Mini App, and the exporter sees lot readiness, an on-time probability and EU-format exports, all on a tamper-evident ledger.

**Architecture:** One Next.js App Router app. Pure domain modules (`src/domain`) hold every rule and algorithm and have no I/O. Integrations (`src/integrations`) are thin clients with injected `fetch`. Durable work runs as Inngest functions (`src/workflows`). Drizzle talks to Neon Postgres in production and to PGlite locally, so the app runs with zero setup.

**Tech Stack:** Next.js 16, React, TypeScript (strict), Tailwind CSS v4, shadcn/ui, MapLibre GL 5, Drizzle ORM 0.45 with Neon serverless and PGlite 0.5, Inngest 4, @google/genai 3, Zod 4, Turf, polygon-clipping, Vitest 5, Playwright.

**Spec:** `docs/Kaffa-Solution-Design-v2.pdf` (live doc: https://claude.ai/artifact/7tyJ32z4SXEis1wz4p3dX4). Tier 1 list is in "Scope and build order".

## Global Constraints

- Free services only, no card. Every key is optional in local dev; missing keys switch that integration to recorded fixtures and the UI says so.
- Rules version string: `RULES_VERSION = "2026-11-11.1"`, stored on every check.
- Blocked threshold: loss after 2020 ≥ min(10% of plot area, 0.5 ha). Any smaller loss or any alert → review. Cut-off date `2020-12-31`.
- Polygon required when area > 4 ha; a Point may stand for a plot ≤ 4 ha. Points are screened as a circle of the declared area (default 4 ha, the EU default).
- Coordinates are truncated (not rounded) to 6 decimals before validation for export; validation runs on the truncated shape.
- EU GeoJSON: FeatureCollection, WGS84 lon/lat, `ProducerCountry: "ET"`, `ProductionPlace`, `ProducerName` optional, `Area` (ha, number) on Points only, no holes, no LineStrings, ≤ 25 MB per file.
- Chase timing: reminder after 48 h, escalation after 96 h, at most 5 outbound messages per field agent per day. All values in `src/config/policy.ts`.
- Forecast: 10,000 runs, seeded PRNG (mulberry32), default seed 42.
- Ethiopia bounding box for sanity checks: lat 3.4 to 14.9, lon 33.0 to 48.0.
- All demo data is synthetic and labelled `synthetic: true`. No real personal data goes to the unpaid Gemini tier.
- Commits use the user's own git identity. No AI attribution trailers or lines anywhere.
- Gemini model comes from `GEMINI_MODEL`; Gemini never sets a status. Only `src/domain/status.ts` does.

## Review Focus

1. Latitude and longitude swapped in an upload (common with spreadsheets) → flagged `swapped_coordinates` with a proposed fix, never silently screened in the wrong country. Test in Task 3.
2. A polygon valid at full precision that degenerates after 6-decimal truncation → `degenerate_after_truncation`, export refuses it. Test in Task 3 and Task 5.
3. A forged Telegram webhook (wrong secret header) or forged or stale Mini App `initData` → rejected with 401. Test in Task 8.
4. Telegram delivering the same update twice, or a reply arriving after escalation → processed once; a late reply still closes the gap. Test in Task 8 and Task 10.
5. A GPS walk with jittery, sparse or crossing points → points with accuracy > 25 m dropped, fewer than 4 distinct points asks for a re-walk, a crossing track is rejected. Test in Task 3.
